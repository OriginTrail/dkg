# WAL-001 protocol-freeze evidence

## Outcome

WAL protocol version 1 is frozen as language-neutral deterministic bytes. The
production runtime is intentionally not scaffolded here; that remains WAL-002.
The existing graph-sync implementation is neither a correctness oracle nor a
performance baseline for this work because its synchronization behavior is
known to be unreliable.

The sole durable content-addressed synchronization atom is the complete
eight-position `WalObjectV1`. Reconciliation contains only `WalObjectId` values.
Adapter payloads, byte ranges, set-commitment nodes/proofs, IBLT symbols,
fallback cursors, receipts, and staging records have no independent content
identity or membership in the reconciled set.

## Artifacts

- `vectors/protocol-v1.schema.json` freezes tuple arities, field types, enum
  values, domains, message types, protocol IDs, the binary64 IBLT schedule,
  and hard limits.
- `vectors/protocol-v1.json` contains valid and invalid golden vectors for
  namespaces, WAL objects, signatures/IDs, signed checkpoints/vectors,
  whole-object ranges, set roots/proofs, IBLT, fallback pages, AES-GCM adapter
  envelopes, snapshots/receipts, replay/conflict outcomes, tier movement, finality,
  authority rollback/downgrade, and cutover.
- `src/reference.ts` and `src/independent.ts` are separately written TypeScript
  consumers. The latter does not call the reference CBOR encoder, WAL verifier,
  set-root builder, symbol encoder, AES decryptor, or replay/conflict evaluator.
- `src/range-staging.ts` and `src/streaming-wal.ts` are test-only reference
  harnesses for the frozen large-object contract. They are not runtime code.

## Acceptance evidence

| Area | Evidence |
|---|---|
| Sole atom and exact tuple | Exact eight-field schema; DKG-field exclusion test; one-byte payload change produces a new whole-object ID. |
| Canonical encoding/signatures/IDs | Valid bytes plus missing, extra, reordered, map, indefinite, non-shortest, altered-payload, and invalid-signature cases. |
| TypeScript-only independent conformance | Generic reference and cursor/schema-specific verifier reproduce bytes, identities, roots, symbols, plaintext, and replay/conflict digests. No Go/Rust/Python conformance implementation is added. |
| Set commitment/proofs | Empty, one, split-257, odd-nibble proof, duplicate/bitmap/root invalid cases. |
| Reconciliation | Exact binary64 membership schedule, signed-i64 symbols, exact symmetric difference, lowest-index peeling, no partial result, reconstructed provider root, and fallback pages. |
| Whole-object transfer | First/middle/final/EOF, duplicate, overlap, out-of-order, cross-provider, restart, dishonest length, overflow, bounds, conflict, physical-byte/part-count quota, cancellation, and cleanup cases. |
| Large object | A generated 16 MiB inline payload is staged and verified with a maximum 64 KiB read buffer, survives a new stager instance, and is absent from the final store until signature/ID/canonical validation and atomic rename. |
| Snapshots/compaction | Exact manifest/entry/conflict/legacy-genesis/receipt schemas and vectors; sequence-zero new-epoch baseline, empty parents/base heads, external-conflict closure, expiring custodian rules. |
| Replay/conflict projection | Shared-core outcomes for causal, concurrent, resolution, and tier scenarios are supplied as inputs; conformance only canonicalizes head sets and computes projection digests. It contains no DKG decision table. |
| Privacy/finality/authority/cutover | Public tier bytes are checked against forbidden private values; effective finality cannot fall below current network policy; signed authority/checkpoint/vector/cutover and stale/downgrade vectors are concrete bytes. |

## Reproduction

```sh
pnpm --filter @origintrail-official/dkg-wal-v1-conformance verify
```

The expected result is 40 passing tests followed by a clean strict TypeScript
check. The generator runs in `--check` mode first, so stale checked-in fixtures
fail the command.

The protocol atom audit is definition-oriented: `PayloadId`, `BlobId`,
`ChunkId`, `RangeId`, and `IbltSymbolId` may appear only in explicit forbidden
lists or prose saying they do not exist. No schema, tuple, identity formula,
set element, fetch request, store entry, or lifecycle defines one of them.
