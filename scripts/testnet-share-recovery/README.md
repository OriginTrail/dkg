# #2963 live recovery comparison

These scripts preserve one-shot request denominators and read-only evidence for the six-publisher, Blazegraph comparison described in `agent-docs/plans/2026-10-16-2963-durable-share-recovery.md`. They do not claim wallet ownership, copy credentials, fund wallets, start daemons, retry HTTP mutations or perform manual repair. Use the DKG testnet skill's native environment setup, exclusive wallet claim and reconciliation workflow first.

The campaign uses a fixed public author address and graph suffix in the scripts. These are public test identities, not portable defaults. A different wallet pool requires an explicitly recorded protocol revision before either comparison arm. Run from the repository root; evidence lives under `.tmp/2963/evidence/<arm>`. `DKG_HOME` must name the owned isolated home. Build the selected revision first and disable auto-update in that home.

1. Start a fresh pinned Blazegraph namespace and a daemon with the target graph persisted in `config.contextGraphs`. For both arms preload the same `fault-hook.mjs` using Node's `--import` option. Set `DKG_TEST_RUNTIME_ROOT` to that daemon's built checkout and launch from that directory. Check its PID-specific `2963-fault-runtime-*.json` attestation points to the same storage/core modules; a preload from another checkout must not patch its own dependencies. Require both target fault latches before claiming injected coverage. Its only activation file is the owned home's `2963-faults.json`; faults are one-shot, fsynced latches. Never use this preload outside an isolated test daemon.
2. Create/register the private graph. Before creating any asset, wait for accepted, current `finalized-chain` authority in catalog mode, the catalog service started, the intended private access/publish policy, and zero legacy rows. An empty catalog may report `bootstrapping` with zero author heads and null expected/applied head digests/counts; this is not the later 180-row completion gate. Preserve the bounded authority observations and setup-gate hash identically for both arms. Then share `readiness-smoke` with the same eight-triple payload generated by `live-run.mjs`. Preserve its response. `node scripts/testnet-share-recovery/live-run.mjs <arm> prepare` creates/shares the other 179 initial assets and prepares 256 sealed drafts. Preparation failures stop the run and remain recorded.
3. Wait for current accepted authority, complete catalog status, exactly 180 catalog/inventory identities and zero legacy rows. Save `node scripts/testnet-share-recovery/snapshot.mjs <arm> pre-workload`. Verify exact identity sets, not only counts. The measured runner independently refuses traffic if its status readiness barrier fails.
4. `node scripts/testnet-share-recovery/live-run.mjs <arm> run` submits 48 publications at concurrency six and 256 synchronous shares at concurrency four. Each mutation is sent once. The main fault protocol targets `catalog-140` (typed not-started failure) and `catalog-141` (untyped failure), both immediately before the promoted lifecycle insertion after deletion. It observes both default and original-author descriptors every 15 seconds after fault activation. A selected fault boundary characterizes partial commits; it does not identify the original production failure's store call.
5. If the runner observes convergence early, retain the daemon and take a second readback at the fixed deadline; early success is not the deadline snapshot. Save `snapshot.mjs <arm> fixed-deadline`, then run `reconcile.mjs <arm> fixed-deadline`, `seal-proof.mjs <arm> fixed-deadline`, `capture-chain-deployment.mjs <arm>`, `chain-proof.mjs <arm> fixed-deadline`, `descriptor-proof.mjs <arm>`, `nonce-proof.mjs <arm>` `fault-identity-proof.mjs <arm> fixed-deadline`, `identity-proof.mjs <arm> fixed-deadline`, and `python3 scripts/testnet-share-recovery/verify.py <arm> fixed-deadline`. The reconciliation helper expects the campaign's public starting wallet inventory at `.tmp/2963/evidence/baseline-balances-nonces.json`. Reducers report gaps; a completed script is not itself a passing correctness verdict.
6. Stop owned writers and supervisors, verify receipts and all used signer pending/latest nonces, then release the matching claim only when quiescent. Preserve the home, store data, failures and incomplete operations. For a new home using the same author, carry only the monotonic KA-number floor to avoid reusing unpublished identities.

The protocol records a 20-minute publication deadline from traffic start and a 20-minute catalog deadline from traffic end. Polls are sampled; use their recorded timestamps to establish deadline coverage and recovery-time bounds. Naturally occurring failures and the two injected requests have separate denominators. Manual repairs must always be reported separately and never count as automatic recovery.

A main-run fault file has this shape (use the actual arm's graph):

```json
[
  {"name":"catalog-140","kind":"typed-not-started","contextGraphId":"<owned graph>","agentAddress":"<original lifecycle author>"},
  {"name":"catalog-141","kind":"untyped","contextGraphId":"<owned graph>","agentAddress":"<original lifecycle author>"}

```

For a separately reported process-crash regression, `kind: "process-exit"` exits the owned daemon with code 86 at that same boundary. The existing foreground supervisor automatically replaces its exited worker on the same home/store; observe it without HTTP replay. The normal lease is 15 minutes; report the fixed restart observation deadline and retain the job if it does not recover. Do not shorten leases by editing stored jobs.

Export reviewer-safe artifacts with `python3 scripts/testnet-share-recovery/reviewer-evidence.py <arm> fixed-deadline`. Its allowlist excludes home files, claim/API tokens and raw logs. The executed baseline/candidate runner copies are frozen in their private evidence directories with matching hashes; the checked-in runner now reads the shared manifest with the same fixed workload; executed private copies remain the recorded frozen revision. `starting-set-proof.mjs <arm>` verifies the complete starting identity sets before measured traffic.

Run `restart-regression.mjs <arm> start` only after the main fixed-deadline observation completes. Run `restart-regression.mjs <arm> observe`, then take `snapshot.mjs <arm> restart-readback`, run `python3 scripts/testnet-share-recovery/restart-content-proof.py <arm>`, and run `restart-identity-proof.mjs <arm> after`. The proofs verify the same binding and operation, exact payloads for all 437 assets, unchanged payload graph presence and authoritative metadata for the original 436 assets, one additional catalog identity, unchanged publication carriers and all signer nonces. Only responses completed within the fixed deadline establish success. The process witness records PID replacement; it does not capture the OS exit status. Its `*-raw-job.json` files contain internal claim capabilities and must never be exported.


After completing restart readback, `python3 scripts/testnet-share-recovery/export-restart.py <arm>` exports only the reviewable proof fields and observations. Inspect `missingEvidence`, every identity assertion, deadline outcome and process witness before claiming success. Never copy `*-raw-job.json`, the home, or API/claim tokens into reports. The full initial 436-entry matched proof remains separate from the later 437-entry restart readback.

`capture-chain-deployment.mjs` is a read-only collector. It checks the RPC chain against the preserved campaign configuration and captures the configured Hub's `DKGKnowledgeAssets` binding with an EIP-1898 `eth_call` pinned to each receipt's exact block hash and `requireCanonical: true`. The offline chain proof requires this separate artifact and rejects foreign emitters, missing/ambiguous bindings and mismatched chain/Hub configuration. Reconciliation must retain receipt `blockHash`; receipt, log and deployment hashes must be valid and equal, with matching block numbers and log transaction hashes. Historical reads that fail do not fall back to numbered/current deployment. Preserve original proofs before revalidating existing arms. If old receipts omitted their top-level block hash, collect supplementary receipts in an isolated copy, verify every original log and receipt coordinate before enrichment, and record the new collection time/provenance; never silently derive the missing field or overwrite original captures.

Inventory snapshots retain every head/row scope for the graph in one SQLite transaction. The proof resolves the single campaign author's lane from captured accepted/current API authority and its expected/applied catalog head digest, then checks graph, author, era, complete scope tuple and persisted row keys. It rejects missing/ambiguous scope provenance, stale authority and obsolete-lane substitution. A `known-incomplete` baseline authority is retained when its expected/applied head agrees; missing rows still fail exact-set comparisons. Raw scopes remain available even when selection fails. Starting, main and restart reducers recompute selection rather than trusting the flat `swm` export, and compare only the authoritative catalog head's rows while retaining all raw catalogs. Legacy snapshots that recorded only the first head cannot establish complete scope coverage; do not upgrade their schema or overwrite them to manufacture that evidence.

Scope selection also validates content commitments: inventory rows use the core signed-head snapshot-binding validator; catalog rows are reconstructed through the selected head's complete content-addressed directory/bucket closure, checking canonical scopes, topology, counts and payload byte lengths. The separately exported row array must match that reconstruction. One persisted applied-head key must match the exact catalog scope, author and head. Both reviewer exporters use this same offline selector, emit `inventory-scope-proof.json` with commitment provenance and excluded-scope summaries, and refuse stale saved identity proofs. They never flatten obsolete catalog rows into current coverage.
