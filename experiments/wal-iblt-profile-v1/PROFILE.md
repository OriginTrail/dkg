# Candidate `ProtocolV1IbltReconciliationAlgorithm`

Status: **experimental, not wire-stable**
Candidate: `paper-baseline-v0`

## Frozen design invariants

These are architecture constraints, not sweep inputs:

1. The reconciled set element is exactly one 32-byte `WalObjectId`.
2. Only a complete canonical `WalObjectV1` is durable synchronized content.
3. IBLT symbols and all reconciliation state are disposable control data and
   never content-addressed atoms.
4. The provider-minus-receiver cell count is a checked signed i64.
5. ID and checksum accumulators are 32-byte XOR sums.
6. A non-zero cell is pure only at count `+1` or `-1` and only when
   `checksumXor == BLAKE3(checkDomain || seed || idXor)`.
7. A zero cell requires count zero, zero `idXor`, and zero `checksumXor`.
8. Provider symbols are consumed in contiguous increasing index order. A
   receiver appends windows without discarding earlier residual or peel work.
9. Peeling always chooses the lowest currently decodable symbol index.
10. Decode output is not accepted until it is unique, within bounds, leaves a
    zero residual, and reconstructs the provider's exact signed count and root.
11. Fallback IDs are strictly sorted, paginated, bound to one signed head, and
    accepted only after exact count/root verification.

## Candidate seed and checksum derivation

Role words replace ambiguous `local` and `remote` labels:

```text
reconciliationSeed = BLAKE3(
  "dkg-wal-iblt-seed-v1\0" ||
  requesterHeadId || providerHeadId || requesterNonce
)

mappingSeed = u64le(first8(BLAKE3(
  "dkg-wal-iblt-map-v1\0" || reconciliationSeed || walObjectId
)))

idChecksum = BLAKE3(
  "dkg-wal-iblt-check-v1\0" || reconciliationSeed || walObjectId
)
```

All three IDs/nonces above are currently fixed at 32 bytes in the lab. The
requester chooses the nonce after verifying the provider's immutable signed
head. A session must not reuse a seed with different head-role ordering.

## Candidate rateless membership schedule

Every ID belongs to symbol zero. Its later symbol indices are generated by a
per-ID cursor. Starting with `state = mappingSeed` and `index = 0`:

```text
state = state * 0xda942042e4dd58b5 mod 2^64
distance = max(1, ceil(
  (index + 1.5) * (2^32 / sqrt(binary64(state + 1)) - 1)
))
index = index + distance
```

This is the paper authors' reference schedule. It makes membership probability
for symbol `i` approximately `1 / (1 + i/2)`, so expected degree is
approximately `N / (1 + i/2)`. There is no separately sampled fixed-table
degree distribution. The multiplier, `1.5` offset, and binary64 rounding are
candidate wire choices until cross-language vectors prove exact agreement.

## Candidate stream and fallback values

| Value | Baseline | Why it is not frozen |
|---|---:|---|
| Initial window | 32 symbols | Small differences may over-transfer; RTT trades against bytes. |
| Window growth | 2x | Needs latency/loss and continuation measurements. |
| Maximum symbols | 1,048,576 | Must be tied to memory, CPU, and elapsed budgets. |
| Maximum decoded difference | 250,000 IDs | Admission/memory policy, not mathematics. |
| Maximum overhead ratio | 2.5x | Needs failure-probability measurements by `k`. |
| Empty receiver | enumerate immediately | Backfill difference equals the full retained set. |

The JSON in `configs/paper-baseline-v0.json` is the editable experiment record.
Any sweep result must name the full config and source revision.

## Candidate canonical binary tuple

The lab now encodes each symbol as one deterministic CBOR value:

```text
[symbolIndex, signedCount, idXor, checksumXor]
```

- the array has exactly four items;
- integers use RFC 8949 shortest-form deterministic encoding;
- `symbolIndex` is a non-negative integer bounded here by the JavaScript safe
  integer limit and `signedCount` is bounded to signed i64;
- both XOR fields are definite-length 32-byte strings encoded with `58 20`;
- indefinite values, non-shortest integers, wrong arity/type/length,
  truncation, overflow, and trailing bytes are rejected.

This is a tested candidate encoding, not yet a normative Protocol V1 vector.
The safe symbol-index maximum should be narrowed to a protocol budget before
promotion; no legitimate reconciliation should approach the implementation
limit.

## Interoperability work still required

Before promotion, freeze and test:

- independent-language confirmation of the candidate CBOR tuple and every
  integer boundary;
- exact mapping behavior at u64 and safe-index boundaries without relying on
  unspecified language math behavior;
- signed-head and requester/provider role binding in request/response frames;
- stable failure codes and budgets for malformed cells, overflow, residual
  cores, duplicate output, checksum mismatch, stale seed, root mismatch, and
  count mismatch;
- adaptive fallback decisions for large differences and adversarial streams;
- golden vectors from empty through split commitment roots, every integer
  boundary, mapping indices, symbol windows, subtraction states, peel trace,
  reconstructed root, and fallback pages;
- byte-identical consumption of those vectors by two independent languages.

The checked-in vector is intentionally labelled experimental and is not
sufficient for protocol conformance.

## Promotion gate

Move this code into the eventual reconciliation package only when:

1. workload sweeps cover equal, sparse, dense, disjoint, genesis/backfill, and
   adversarial cases through the RFC's `N = 10^6` targets;
2. the selected profile meets stated byte, CPU, memory, and failure-rate goals;
3. unit, property, fuzz, malformed-input, and resource tests meet the WAL-005
   100% coverage requirement;
4. two independent implementations consume the final vectors; and
5. the RFC replaces every candidate choice with exact normative language.
